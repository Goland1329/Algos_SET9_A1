# Отчет по лабораторной работе: Эмпирический анализ алгоритмов сортировки строк

В данном отчете представлен сравнительный анализ производительности классических алгоритмов сортировки (QuickSort, MergeSort) и их специализированных модификаций для работы со строками (Тернарный QuickSort, String MergeSort с кэшированием LCP, MSD Radix Sort и гибридный Radix + QuickSort).

## 1. Анализ времени выполнения

### Случайный массив

Для неупорядоченных наборов строк выявлены следующие закономерности:

* Минимальное время выполнения продемонстрировал гибридный алгоритм **Radix + QuickSort** (~6.85 мс для 3000 элементов). Данный подход компенсирует накладные расходы MSD Radix на выделение корзин за счет обработки мелких подмассивов алгоритмом QuickSort.


* Классический **MSD Radix** работает в 2 раза медленнее гибридного подхода (~14.74 мс)  из-за издержек на аллокацию массивов для 128 корзин на нижних уровнях рекурсии.


* 
**Стандартный MergeSort** (~9.42 мс) незначительно превзошел **Оптимизированный MergeSort** (~10.29 мс). На случайных данных совпадающие префиксы строк минимальны, поэтому выгода от кэширования не окупает накладные расходы на поддержание структуры данных `pair<string, int>`.



### Обратно отсортированный массив

Данный набор данных продемонстрировал уязвимости реализаций:

* 
**Стандартный QuickSort** показал значительную деградацию производительности (около 6942 мс для 3000 элементов), что характерно для временной сложности $O(N^2)$ при фиксированном выборе опорного элемента.


* Оптимизированный (тернарный) **QuickSort** показал более стабильный результат, однако время выполнения осталось высоким (~202 мс).


* Гибридный алгоритм **Radix + QuickSort** уступил классическому **MSD Radix** (~77.3 мс против ~61.6 мс). Снижение производительности вызвано переключением на QuickSort, неэффективно обрабатывающий обратно отсортированные последовательности.


* Наибольшую стабильность продемонстрировали обе реализации **MergeSort**, выполнив сортировку за ~37-39 мс.



### Почти отсортированный массив

* 
**Стандартный QuickSort** вновь продемонстрировал низкую эффективность (~339 мс)  из-за многократных избыточных сравнений длинных совпадающих префиксов.


* Наилучшие результаты показали алгоритмы слияния: **Оптимизированный MergeSort** (~38.7 мс) и **Стандартный MergeSort** (~39.7 мс)  отработали практически за идентичное время.



## 2. Анализ количества посимвольных операций (сравнений)

Оценка количества операций доступа к символам подтверждает теоретическую эффективность специализированных алгоритмов:

* 
**Избыточность операций базовых алгоритмов:** На массиве из 3000 почти отсортированных строк стандартный QuickSort совершил более 944 000 посимвольных сравнений. Стандартные методы выполняют повторные проверки одинаковых начальных частей строк.


* **Эффективность кэширования префиксов:** Оптимизированный MergeSort, использующий алгоритм LCP, стабильно демонстрирует кратное сокращение количества сравнений по сравнению со стандартной реализацией. На случайных данных имеем ~36.6 тыс. операций против ~44.4 тыс. у стандартного. На почти отсортированных: ~23.8 тыс. против ~41.8 тыс..


* 
**Стабильность MSD Radix:** Классический MSD Radix выполнил ровно **7259 инспекций символов** на массиве из 3000 строк во всех трех сценариях (случайном , обратном и почти отсортированном ). Распределяющая сортировка нечувствительна к начальному порядку элементов: количество операций зависит исключительно от числа и длины строк.



## Вывод

1. Применение классической сортировки QuickSort в чистом виде для массивов строк неэффективно: алгоритм подвержен деградации до $O(N^2)$ при неудачных конфигурациях данных и совершает избыточное число операций при наличии длинных общих префиксов.


2. Классический MergeSort является универсальным решением. Оптимизация работы с памятью обеспечивает высокую скорость , хотя алгоритм и проигрывает строковой модификации по количеству логических сравнений.


3. Оптимальным выбором для сортировки строк на практике является гибридный подход **MSD Radix + QuickSort** (для случайных распределений) или улучшенный **MergeSort** (при необходимости строгой гарантии времени выполнения $O(N \log N)$ на любых данных).
