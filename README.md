# Отчет по лабораторной работе: Эмпирический анализ алгоритмов сортировки строк

В данном отчете представлен сравнительный анализ производительности классических алгоритмов сортировки (QuickSort, MergeSort) и их специализированных модификаций для работы со строками (Тернарный QuickSort, String MergeSort с кэшированием LCP, MSD Radix Sort и гибридный Radix + QuickSort).

Тестирование проводилось на наборах от 100 до 3000 строк для трех конфигураций данных: случайного, обратно отсортированного и почти отсортированного массивов.

## 1. Анализ времени выполнения

### Случайный массив
Для неупорядоченных наборов строк зафиксированы следующие результаты:
* Минимальное время выполнения продемонстрировали **Стандартный MergeSort** (~7.20 мс для 3000 элементов) и гибридный алгоритм **Radix + QuickSort** (~7.27 мс).
* Классический **MSD Radix** работает медленнее гибридного подхода (~15.84 мс). Разница в производительности обусловлена издержками на создание массивов для 128 корзин на нижних уровнях рекурсии.
* **Стандартный MergeSort** (~7.20 мс) превзошел **Оптимизированный MergeSort** (~8.10 мс). На случайных распределениях длины совпадающих префиксов минимальны, вследствие чего снижение количества сравнений не компенсирует накладные расходы на поддержание структуры данных `pair<string, int>`.

### Обратно отсортированный массив
Данный набор данных выявил структурные уязвимости тестируемых алгоритмов:
* **Стандартный QuickSort** показал критическую деградацию производительности (около 5718 мс для 3000 элементов). Такое время выполнения соответствует теоретической сложности $O(N^2)$ при выборе крайнего элемента в качестве опорного.
* Оптимизированный (тернарный) **QuickSort** отработал за ~199.5 мс, что подтверждает его уязвимость к обратно отсортированным последовательностям.
* Гибридный алгоритм **Radix + QuickSort** уступил классическому **MSD Radix** (~77.8 мс против ~63.0 мс). Падение производительности вызвано переключением на алгоритм QuickSort для сортировки малых подмассивов.
* Минимальное время на данном наборе показал **Стандартный MergeSort** (~6.32 мс), в то время как **Оптимизированный MergeSort** затратил ~54.80 мс. 

### Почти отсортированный массив
* **Стандартный QuickSort** продемонстрировал низкую эффективность (~245.5 мс) вследствие многократных избыточных сравнений длинных совпадающих префиксов.
* Наилучший показатель времени выполнения зафиксирован у алгоритма **Стандартный MergeSort** (~21.80 мс). **Оптимизированный MergeSort** выполнил сортировку за ~39.00 мс.

## 2. Анализ количества посимвольных операций (сравнений)

Анализ количества сравнений символов:

* **Избыточность операций базовых алгоритмов:** На массиве из 3000 почти отсортированных строк стандартный QuickSort совершил более 944 000 посимвольных сравнений. Базовые алгоритмы многократно считывают совпадающие префиксы строк.
* **Эффективность кэширования LCP:** Оптимизированный MergeSort демонстрирует стабильное сокращение количества логических сравнений по сравнению со стандартной реализацией. На случайных данных зафиксировано ~27.9 тыс. операций против ~44.4 тыс. у стандартного алгоритма. На почти отсортированных: ~16.3 тыс. против ~41.8 тыс. операций.
* **Стабильность MSD Radix:** Классический MSD Radix выполнил ровно **7259 обращений к символам** на массиве из 3000 строк во всех трех сценариях тестирования. Алгоритм распределяющей сортировки нечувствителен к изначальному порядку элементов: количество операций строго зависит от количества и длины строк.

## Вывод

1. Применение классической сортировки QuickSort для массивов строк нецелесообразно: алгоритм подвержен деградации до $O(N^2)$ при специфических конфигурациях входных данных и совершает избыточное число посимвольных операций при наличии длинных общих префиксов.
2. Классический **MergeSort** демонстрирует высокую производительность по времени. Отсутствие накладных расходов на создание сложных структур данных обеспечивает преимущество в скорости выполнения, несмотря на большее количество логических сравнений.
3. Исходя из результатов эмпирического анализа, оптимальным выбором для практического применения является **Стандартный MergeSort** (в случаях, где требуется строгая гарантия времени $O(N \log N)$) и гибридный **MSD Radix + QuickSort** (на массивах со случайным распределением данных).
